# Treat each scanner run attempt as an immutable session

Each scanner run attempt is stored as a separate immutable Scanner Session, including failed, cancelled, and Partial Sessions; a retry never revises its predecessor. A Partial Session is terminal and has a usable, internally consistent Candidate set, but at least one source or stage required by its Scanner Policy did not complete; ordinary Unknown Evidence does not make a session partial. A session receives a fixed Trading Date and Market Phase when it starts, determined from the official U.S. exchange calendar in America/New_York time, and crossing a phase boundary never mutates that identity. Only a completed session may become the Actionable Current Session; a newer partial, failed, or cancelled attempt remains visible without replacing the last qualifying completed session. This status is derived rather than persisted as mutable session state. The model costs more storage and requires explicit selection logic, but preserves the evidence actually available during each attempt and makes failures, retries, audits, and historical replay deterministic.

Running progress is visible only as operational state. Candidates from a running attempt never leak into the Actionable Current Session; after the run reaches completed, its promotion occurs atomically in one database transaction. Partial, failed, and cancelled attempts cannot be promoted, so the scanner never presents a mixed or half-enriched result as current.

The manual-first milestone permits one active scanner run globally. A repeated Run scanner request returns the existing active run and its progress rather than issuing duplicate provider calls; another run may start only after the active attempt reaches a terminal state. More granular concurrency is deferred until operating experience demonstrates a need.
